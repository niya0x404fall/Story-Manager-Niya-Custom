# Ручная проверка Story Manager · Niya Custom 0.4.8

Проводите тесты в отдельном чате. Перед заменой расширения экспортируйте JSON Story Manager.

## 1. Точный интервал без учёта автора

1. Установите интервал `2` и включите автоматику.
2. Отправьте или получите три видимых сообщения в любом порядке авторов.
3. После третьего сообщения должна появиться одна карточка из первых двух сообщений.
4. Третье сообщение должно остаться защитным хвостом для следующей карточки.

Карточка может заканчиваться сообщением пользователя или персонажа. Автор не влияет на диапазон.

## 2. Скрытые сообщения не считаются

1. Оставьте интервал `2`.
2. Создайте одно видимое сообщение, затем неудачный ответ и скройте его.
3. Создайте ещё одно видимое сообщение.

Запрос пока не должен начаться: накоплены два видимых источника и один из них остаётся защитным хвостом. После следующего видимого сообщения карточка должна содержать первые два видимых источника и не содержать скрытый ответ.

## 3. Hide во время запроса

1. Поставьте медленный профиль и интервал `2`.
2. Доведите очередь до запуска автоматики.
3. Пока модель готовит саммари, скройте одно из выбранных сообщений.

Полученный по старому набору ответ не должен создать карточку. Следующий запуск должен построить новый план без скрытого сообщения.

## 4. Готовое саммари и архивирование

1. Создайте карточку по видимым сообщениям.
2. После её сохранения скройте исходные сообщения.

Карточка не должна стать красной и должна остаться включённой в контекст. Это режим замены сырой старой истории готовой выжимкой.

## 5. Ручной остров и frontier

Подготовьте покрытие до `119`, оставьте `120–129` без карточки и вручную создайте `130–137`.

Ожидаемый порядок автоматики:

1. Отдельная partial-карточка `120–129`.
2. Готовая `130–137` не создаётся повторно.
3. Следующая автоматическая карточка начинается с `138`.

При создании `130–137` до заполнения дыры должно появиться предупреждение, что модель не увидит summary-контекст `120–129`.

## 6. Предупреждение после остановленного запроса

1. Оставьте одно видимое непокрытое сообщение, следующее сообщение скройте.
2. Вручную выберите более поздний диапазон из одного сообщения.

До запроса должно появиться предупреждение с номером оставшегося видимого сообщения. Нажатие «Отмена» не создаёт карточку и не расходует запрос.

## 7. LinkAPI и отсутствие повторов

1. Выберите Custom Connection Profile с LinkAPI.
2. Создайте одну тестовую карточку.

Потоковый ответ должен разобрать штатный SSE-парсер SillyTavern. При ошибке `524`, обрыве или повреждённом потоке Story Manager показывает ошибку и не отправляет второй запрос автоматически. Повтор возможен только новым действием пользователя.
